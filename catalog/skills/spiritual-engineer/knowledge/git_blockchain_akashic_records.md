# Gitとブロックチェーンのハッシュチェーンから見るアカシックレコード

# はじめに

普段は開発の中でGitやブロックチェーンのハッシュ構造に触れているが、ある日ふと、これらの「改ざん不可能な記憶の連鎖」という仕組みが、アカシックレコード(魂の記憶の連なり)の構造そのものではないかと気づいた。
この記事では、その類推についてまとめる。

## Gitのハッシュチェーンと魂の記憶

Gitの各コミットのハッシュ値は、そのコミットの中身(ファイルのスナップショット)と、親コミットのハッシュ値から計算される。もし過去のどこか1つのコミットの中身を書き換えれば、そのハッシュが変わり、それ以降の全コミットのハッシュも連鎖的に変わってしまう。つまり、一部だけをこっそり消す・書き換えることは構造的にできない。

アカシックレコードも同じ構造を持つと考えられる。前世ごとの記憶が点として連なり、その連なり全体が魂(個)を構成している。記憶の一部だけを切り離して消すことはできず、すべての記憶が繋がったまま存在し続ける。

さらに興味深いのは、Gitのコミットハッシュが「中身から計算されるID」であるという点(content-addressable storage)。IDが先にあって中身を後から割り当てるのではなく、中身そのものがIDになる。これを魂に当てはめると、魂という「ラベル」が先にあって記憶を後付けしているのではなく、蓄積されたすべての記憶(前世の点の連なり)そのものが計算されて、魂という固有の"ハッシュ値"=個性になっていると考えられる。

## プルリクエストとmainへのマージ ― 段階的な収束

このハッシュチェーンには、実は「確定する前」と「確定した後」という段階がある。Gitには、ローカルやPRのブランチ上では一度コミットしたものを書き換えられる、という性質がある。正確には、`git reset --hard` や `git rebase` によって、ブランチの指し示す先を過去に巻き戻す/コミット列を新しいハッシュで作り直すことで、それ以降のコミットを到達不能(unreachable)にする操作である。到達不能になったコミットは即座には物理削除されず、reflogという記録と共に一定期間(デフォルト30〜90日)残った後、`git gc`が走って初めて本当に消える。PRのブランチにforce-pushして書き換えることも、レビュー中は普通に行われる。

PR(プルリクエスト)を開くというのは、「この変更をmainに取り込みたい」という提案を、レビュアーたちに向けて broadcast する行為に近い。レビュアーはコメントを残し、変更を要求し、著者はそれを受けて修正し、再度レビューを依頼する——これを何度かのラウンドにわたって繰り返す。ブランチ保護ルールで「必要な承認数(例: 2人以上のApprove)」が設定されていれば、その閾値に達するまでこのラウンドは終わらない。必要な承認が揃って初めて、mainへのマージが許可される。

これは量子力学における観測と収束、それも一度で決まるのではなく、複数の観測者(レビュアー)との相互作用を通じて徐々に1つの状態へ収束していく**デコヒーレンス**によく似ている。

- **PRのブランチ(マージ前)** = まだ観測されていない重ね合わせの状態。何度でもamendし、rebaseし、なかったことにできる、複数の可能性が並行して試せる「パラレルワールド」
- **レビューのラウンド** = 複数の観測者(レビュアー)との相互作用によって、提案が少しずつ絞り込まれていく過程
- **必要な承認数への到達(マージ)** = 段階的な収束の先にある確定
- **main(確定後)** = アカシックレコード。観測され、複数の証人によって確定された履歴は、もう改変できない

一度mainにマージされ、他の誰かがpullした、CIがログを残した、別ブランチにマージされた、ということが起きた瞬間、その情報は複数の独立した場所に複製されて存在するようになる。技術的には`git push --force`でmainの履歴を書き換えること自体は可能だが、複数の証人(他者のローカル環境・CI・フォーク)が既にそれを観測している限り、その痕跡は事実上消せなくなる。

同じ収束のプロセスは、ブロックチェーンにも見られる。ある取引がまだ**mempool(未承認トランザクションプール)**にある間は、複数のノードがそれぞれ異なる順序・組み合わせで次のブロック候補を作ろうとしている、いわば重ね合わせの状態である。バリデーターがブロック(XRPレジャーでは"レジャー"と呼ばれる)を提案し、コンセンサスアルゴリズム(信頼するバリデーターのリスト=UNL〈Unique Node List〉のうち80%以上の合意)によって多数のノードがそのブロックに合意した瞬間、初めてそれは唯一の確定した状態(ファイナライズされたブロック)に収束する。

XRP Ledger Consensus Protocolでは、この収束が一度の勝者総取りではなく、段階的な調整によって起きる。各バリデーターはまず自分が受け取った取引をローカルな候補セットとしてまとめ、それをUNLの仲間に提案として broadcast する。数秒間隔で複数ラウンドの投票を繰り返し、毎ラウンド、多くの仲間が含めている取引は自分の提案にも残し、少数派の取引は落とす、という調整を行う。これを繰り返すうちに、UNL全体の提案がだんだん同じ集合へと収束していき、80%以上が同じ取引セットに合意した時点で確定する。これは、量子力学における**デコヒーレンス**(重ね合わせが、観測者同士の相互作用によって徐々に1つの状態へ収束していく過程)に近い。1人の勝者が一瞬で決めるのではなく、複数のわずかに異なる候補が、何度もの相互参照を経てゆっくり1つに定まっていく——アカシックレコードへの記録も、同様に一度きりの断定ではなく、複数の意識が繰り返し照らし合わされる中で、じわじわと1つの確定した記憶へと定まっていくのかもしれない。

- **mempool(承認前)** = まだ観測されていない、複数の可能性が並行して存在する重ね合わせの状態
- **コンセンサスによる確定(ファイナリティ)** = デコヒーレンス。複数のノードという"観測者"同士が、何度もの相互参照を経て、徐々に唯一の現実へと収束していく
- **確定済みのチェーン** = アカシックレコード

つまりGitでは「レビューを経たマージ=観測」、ブロックチェーンでは「コンセンサスによるファイナリティ=観測」であり、どちらも「まだ誰にも観測されていない可能性の重ね合わせ」から、複数の観測者との相互作用を経て段階的に、「複数の証人の合意によって確定した、唯一の不可逆な記録」へと収束する、まったく同じ構造を持っている。

ここから見えてくるのは、すべての思考・迷い(ローカルやPRでの試行錯誤、mempool内の未確定な候補)がアカシックレコードに刻まれるわけではなく、実際に選び取られ、世界に対して確定した(レビューを経てマージされた、あるいはコンセンサスでファイナライズされた)ものだけが刻まれる、という見方である。これは多くの精神的伝統で言われる、「思っただけでは業(カルマ)にならないが、それを行動として選び取り、世界に対して確定させた瞬間に刻まれる」という考え方と一致する。頭の中で何度も迷い、書き直す自由意志のプロセス自体は記録ではなく、ただの試行錯誤。そこから一つを選んでPRを出し、レビューを経てマージした——実際に行動し、世界(他者・現実)に観測される形にした——その瞬間だけが、アカシックレコードという不可逆な記録として残るのかもしれない。

## ブロックチェーンの改ざん耐性とアカシックレコードの不可侵性

ここまでは「確定する瞬間」に焦点を当てたが、そもそもGitのコミットハッシュチェーン(冒頭で触れた、中身から親コミットまで連鎖的に計算される仕組み)と同じ原理で、ブロックチェーンも最新ブロックのハッシュ値に全ブロックのデータが実質含まれており、過去のどこか1つのブロックを改ざんすればチェーン全体の整合性が崩れるため、改ざんが構造的に検知される。

ただし、ブロックチェーンの不可逆性は暗号(ハッシュチェーン)だけで成立しているのではない。実際には2つの層に分かれている。

1. **ハッシュチェーン** = 改ざんが起きたことを検知できる仕組み(整合性・完全性)
2. **コンセンサスアルゴリズム** = 「どのチェーンが正しい/確定したものか」を、多数のノードの合意によって決める仕組み(確定性・ファイナリティ)

先述のXRP Ledger Consensus Protocol(UNLの80%以上の合意)は、まさにこの2層目にあたる。UNLの20%を超えるバリデーターが不正・故障していても、80%未満である限り合意は成立せず、ネットワークは前に進まない——つまり閾値を下回る限り、そもそも「確定」自体が起きない設計になっている。

つまりブロックチェーンの不可逆性も、実は上記のGitのリモートの話(多くの証人が同じものを見た)とまったく同じ原理を、数学的に厳密なプロトコルとして形式化したものである。暗号学的な改ざん不可能性と、社会的・分散的な不可逆性は別物ではなく、**不可逆性とは、暗号や物理法則そのものではなく、独立した複数の観測者・証人の合意によって生まれる**、という一つの原理の、非公式版(Git)と公式プロトコル版(ブロックチェーン)の関係にある。繰り返しになるが、カルマが刻まれるのも、1人の心の中の迷い(ローカル)ではなく、複数の意識・魂による合意を経て初めて、"確かにそれが起きた"と確定するのかもしれない。

## アカシックレコードへの接続制限

では、そうして一度確定し不可侵になった記憶に、なぜ今の私たちはアクセスできないのか。地球にいて前世を思い出せないのは、記憶が消去されているからではなく、アカシックレコードという分散台帳への接続能力が制限されているだけだと考えられる。ブロックチェーンのノードが一時的にオフラインになっても、他のノードには全履歴がそのまま残っているのと同じで、消えているのではなく、今そこに接続できていないだけである。

この「接続の制限」は、WiFiなどの電波干渉に例えるとより正確にイメージできる。2.4GHz帯は電子レンジ・Bluetooth・近隣の無数のルーターなど、同じ帯域に多くの機器がひしめき合っているため、信号自体は届いているのに、ノイズに紛れて綺麗にデコードできないことがある。これはSN比(信号対雑音比)の劣化であり、「信号が弱い・届かない」のではなく「信号は届いているが、周囲のノイズに埋もれて拾えない」という状態である。

地球(3次元)は、物質の密度、他者の思考・感情、五感からの膨大な情報が同じ"帯域"で常に鳴り響いている、極度に混雑した環境だと考えられる。アカシックレコードの信号自体は常にそこにあり途切れてはいないが、周囲のノイズのSN比があまりに悪いため、クリアにデコードできない。高次元は、競合するノイズが少ないクリーンな帯域であり、同じ信号でもはるかにクリアに、瞬時に受信できる。

瞑想やタロット・内観といった実践は、信号を強めるのではなく、周りの雑音(思考・感情・執着)を減らすノイズキャンセリングに相当する。前世の記憶が"急に"腑に落ちる瞬間は、信号が新しく届いた瞬間ではなく、ノイズが一瞬静まってSN比が上がった瞬間なのかもしれない。

なお、以前の記事([エンジニアにも役立つ！物理学×スピリチュアルで見る現実化の仕組み](4a6d797986117b123a4a.md))で触れた「3次元は氷のように波動が固まった状態、高次元は水蒸気のように自由に広がった状態」という話は、これとは別の側面——現実化にかかる時間差——を説明するものであり、矛盾するものではなく補い合う関係にある。

## Merkle Proofという「ショートカット」

接続の帯域が確保でき、ノイズが静まったとしても、アカシックレコードに接続できたとき、全記憶を線形に(前世の順番通りに)思い出す必要はないと考えられる。

ブロックチェーンには、ある1つの取引が本当にそのチェーンに含まれているかを、全履歴を最初から再生せずに検証できる仕組みがある。Merkle Tree(マークル木)と呼ばれる構造で、圧縮された「証明の道筋」(Merkle Proof)だけを辿れば、一瞬で「これは確かに繋がっている」と検証できる(SPV検証)。

前世の記憶がタロットや内観を通じて"急に"腑に落ちる瞬間があるとしたら、それは全生涯を順番に再生しているのではなく、Merkle Proofのように必要な一点だけを、圧縮された経路で直接検証・取得しているのかもしれない。

## 最後に

Gitやブロックチェーンが実現しているのは、「改ざん不可能な、圧縮された、コンテンツそのものがアイデンティティになる記憶の連鎖」である。それは、人類が技術の言葉で無意識に再現している、アカシックレコードの構造そのものだと考えられる。
